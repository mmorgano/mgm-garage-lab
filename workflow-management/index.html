01 / CONTINUITY

Pick up the work with its context intact.

A project can span many conversations. Each new session needs a clear starting point.

Remember the decision

Keep the reasoning behind a choice, alongside the work it affects.

See where you stopped

Restore open tasks, blockers and progress without searching old conversations.

Know what comes next

Leave a concrete next step that you or a supported assistant can pick up later.

02 / A READABLE HANDOFF

The next session has somewhere to start.

Imagine a CSV import feature. You close today's session and leave this context for tomorrow.

ILLUSTRATIVE SESSION RECORD
DECISION Validate every row before writing any records.
CURRENT STATE Validation is implemented. The error report needs clearer line numbers.
NEXT STEP Add a test for an invalid row, then finish the error report.

In the next conversation, ask to resume the work. The assistant reads the configured context and uses the handoff to establish the next step. You can inspect and correct the same files.

03 / USER CONTROL

Your context. Your files.

During setup, you choose where ai-context lives. The skill maintains ordinary Markdown and JSON in that location.

Inspect and edit

Open the records with a normal text editor. See what was saved and revise it when needed.

Choose the boundary

Share one context across related projects, or use separate roots when their histories should stay independent.

Use your file tools

Back up or version the records when appropriate. The skill requires no external storage service.

Your assistant needs access to the chosen location and operates under its own permissions and data-handling settings.

04 / PORTABILITY

The workflow belongs to the project,
not to the assistant.

Supported AI assistants can operate on the same project context. Shared files and a common workflow contract carry the working state between conversations.

Codex

Supported package. Manual acceptance test documented.

Claude Code

Supported adapter. Manually tested with a scratch context.

Kiro PUBLIC BETA

Separate package with an optional team mode. The team mode is experimental and untested. Try it on GitHub ↗

Each assistant needs the correct adapter and access to the same configured files. File-based portability does not provide automatic device synchronization or simultaneous editing coordination.

06 / DURABLE KNOWLEDGE

Keep more than the task list.

Sessions and project state Daily logs, decisions, a current RECAP.md and the latest handoff.
Tasks and planning Numbered work items, execution plans, progress and optional sprints.
Study notes and ideas Focus notes that preserve research, findings and evolving analysis.
Meetings and calls Outcomes, decisions, owners and follow-ups that remain available later.
Project direction Roadmaps with milestones, sequencing and dependencies beyond the active session.

07 / YOUR EXISTING TOOLS

Working context alongside Git, Jira and docs.

Git preserves source history. Jira tracks issues. Documentation explains the system. Workflow Management preserves the decisions, progress and next steps that connect AI-assisted sessions.

It complements these tools without replacing them. It is most useful when work spans several sessions. For a one-off question with nothing to preserve, the extra structure may be unnecessary.
