Workflow Management / Active open source

AI conversations are temporary. Your work should not be.

Workflow Management keeps decisions, tasks, notes and handoffs in a project-controlled context folder, so supported assistants can resume with the work already grounded.

01 / Problem

The assistant can help, but the conversation forgets.

Real work spans sessions. Decisions are made, blockers appear, tasks change shape and the next session needs a trustworthy starting point. Without a durable context, every restart becomes reconstruction.

Decisions vanish

The reasoning behind a choice often lives only in chat history, where it is hard to inspect and easy to lose.

Tasks drift

Open work, blockers and next steps become scattered across conversations instead of staying with the project.

Handoffs are weak

A later assistant needs context, not just a fresh prompt and a hopeful summary.

02 / Approach

Project-controlled context

A readable file system for working memory.

During setup, the user chooses where the context lives. The skill maintains ordinary Markdown and JSON records for recaps, sessions, tasks, notes, meetings and roadmap items. The files can be inspected, corrected, backed up or versioned with normal tools.

Start

Restore current tasks, blockers and the previous handoff before work begins.

Work

Capture useful decisions and findings while the project changes.

Close

Update the recap and leave a concrete next step for the next session.

Portability

The workflow belongs to the project, not one assistant.

Supported adapters can operate on the same project context. The shared files carry the working state between conversations, while each assistant still follows its own permissions and capabilities.

04 / Next

Give the next session somewhere to start.

The project is most useful when work spans more than one sitting. For one-off questions, the structure may be unnecessary; for real projects, it turns continuity into something visible and correctable.
